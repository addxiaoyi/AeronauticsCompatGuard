Audit the mixin layer instead of trusting require = 0

Every injector uses require = 0 so a target signature change cannot crash the game, which is
also how the sendPairingData guard stayed silently inactive on NeoForge 21.1.250. Each mixin now
carries a @Unique marker field and MixinAudit verifies it on the target class at server start
and through /acg mixins: 4 APPLIED, 2 skipped because the optional mod is absent, 1 client-only
skip, missing=0, on a real dedicated server.

Also: explicit priority 900 on every server mixin so ordering against default-priority mods is
deterministic, a README table of target/injection/priority/rationale, and two rules learned here:
never probe a client class to detect the side (RuntimeDistCleaner throws and takes the server
down), and wrap the audit so a diagnostic cannot crash the game.
