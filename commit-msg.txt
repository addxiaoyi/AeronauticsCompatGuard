Record failed loot tables as explicit empty tables

A supplied server log had 555 of 690 ERROR lines from LootDataType: loot tables that railways,
dndecor, create_connected, idas and create_enchantment_industry pre-generate for mods that are not
installed (natures_spirit, twilightforest, blue_skies, tfc, hexcasting). Vanilla logs the parse
error, returns Optional.empty(), and the id then simply does not exist.

LootTableParseGuardMixin substitutes the codec's own defaultValue for such ids and records the id,
registry and reason in the quarantine log, so the failure becomes a queryable record instead of a
silently missing table. Vanilla's ERROR line is deliberately left untouched -- nothing is silenced.

Note the limit: this does not remove the 555 ERROR lines, because those are written before the
return value is modified. Removing them needs the referencing tables not to load at all (install
the missing mods, or filter those paths out of the datapack).

Verified on NeoForge 21.1.250: 'Enabled minecraft.loot_table_parse_guard', /acg mixins reports
APPLIED (applied=6 missing=0 declared=9), /acg selftest still 11/11. The registry entry needed the
real three-parameter deserialize signature; with one parameter it was skipped as 'target API
unavailable' while the mixin itself had already applied.
